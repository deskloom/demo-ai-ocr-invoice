# 請求書・領収書のAI読み取り → 表(CSV/Excel)にするツール(ポートフォリオ用デモ)

中小企業の経理担当を想定したデモです。取引先から届いた **請求書・領収書(PDF/画像)** をまとめて読み込ませると、Gemini API が「発行元・日付・書類番号・品目・小計・消費税・合計・インボイス登録番号」などを抜き出し、**一覧表(CSV/Excel)** にします。AI の読み取りミスは AI に任せず **機械的なチェック(コード)で検証し「要確認」に振り分け** ます。ここがデモの見せ場です。

すべて **架空の書類・架空の会社** で作っています。実在の書類は入れないでください。

## できること

- ブラウザ画面: 複数ファイルをドラッグ&ドロップ → 読み取り結果の一覧表示(要確認の行は赤色+理由) → 画面上で値を修正 → CSV / Excel(.xlsx)でダウンロード
- CLI: `npm run extract -- samples/*.pdf --out out/result.xlsx` (拡張子で xlsx/csv/json を切替)
- 機械チェック 1〜8(下記)で要確認を自動判定。二重登録の検出もあり
- サンプル書類 14 件(`samples/`)と正解(`samples/expected/*.json`)を同梱。誤り入りの書類は要確認になる想定
- `npm test`: Gemini を呼ばない単体テスト(偽AI応答)。`npm run eval`: 本物の Gemini API で全サンプル×3 回の評価

## できないこと

- 手書き文字の高精度な読み取り(印刷された請求書・領収書の想定)
- 外貨の為替換算、複雑な値引き・相殺の自動解釈(読み取った値の機械チェックのみ)
- 会計ソフトへの自動仕訳・自動送信(本ツールは表にするまで)
- 完全な精度保証。AI の読み取りはぶれるため、必ず「要確認」行を人間が確認してください

## 画面の使い方

1. `npm install` → `.env` に `GEMINI_API_KEY` を設定(後述) → `npm run dev` → http://localhost:3000 を開く
2. PDF/PNG/JPG/WEBP を最大 10 件・1件 20MB までドラッグ&ドロップ(またはファイル選択) →「読み取る」
3. 一覧に結果が出る。要確認の行は赤色で理由が表示される
4. 各セルを直接編集して修正できる。編集するとサーバー側で機械チェックをやり直し、要確認と理由が更新される
5. 「CSVで保存」「Excelで保存」でダウンロード。Excel には「一覧」シートと「明細」(品目行)シートが入る
6. API キーなしで触りたい場合は「サンプルデータで試す」(ダミー1件表示・保存操作の確認用)

## チェック項目(機械チェック 1〜8)

| # | 内容 | 例 |
|---|---|---|
| 1 | 品目の `数量×単価 = 金額`(各行) | 2×1000≠2001 → 要確認 |
| 2 | 品目金額の合計 = `subtotal` | 品目合計3500≠小計3501 → 要確認 |
| 3 | 税率ごとの税額 = 対象額×税率の端数処理(切り捨て・四捨五入・切り上げのいずれか)と一致 | 10000×10%≠1001 → 要確認 |
| 4 | `subtotal + 税額合計 = total` | 小計+税≠合計 → 要確認 |
| 5 | 登録番号が `T`+13 桁の形式、かつチェックデジット(法人番号の検査用数字: 下12桁を右から1,2,1,2…で加重→合計を9で割った余りを9から引く。10は0)が正しい | 形式違い・検査数字違い → 要確認。無記載(null)はOK |
| 6 | 日付が実在する日付で `dueDate >= issueDate` | 2026-02-30、期限<発行日 → 要確認 |
| 7 | 必須項目の欠落(発行元・発行日・合計) | いずれか欠落 → 要確認 |
| 8 | 同じ書類の二重登録(発行元+書類番号+合計が同じもの。2件目以降を要確認) | 重複投入 → 要確認 |

## セットアップ

- Node.js 22 以上
- `npm install`
- `.env.example` をコピーして `.env` を作り、`GEMINI_API_KEY` を設定。`GEMINI_MODEL` は既定 `gemini-3.8-flash`(変える場合のみ指定)
- API キーは [Google AI Studio](https://aistudio.google.com/apikey) で取得。**請求先アカウントを設定していないプロジェクト** のキーを使えば無料枠で動きます
- 無料枠では送った内容が Google の改善に使われうるため、**実在の書類を入れないでください**(本リポジトリのサンプルはすべて架空です)
- サンプル再生成: `npm run make-samples`(日本語フォント Noto Sans JP を自動取得。取得できない環境ではローマ字で生成)

### コマンド

- 画面: `npm run dev` → http://localhost:3000
- CLI: `npm run extract -- samples/inv-01-clean-10pct.pdf --out out/result.xlsx`
- テスト: `npm test`
- 評価(要APIキー): `npm run eval` → `eval/results.md` に出力。キー未設定なら「GEMINI_API_KEY が未設定です」と表示して終了します
- 呼び出し間隔の既定は 4 秒(`GEMINI_MIN_INTERVAL_MS` で変更可)。1分あたりの回数制限(429)のときは指定された秒数だけ待って最大 3 回再試行します
- 評価のオプション: `npm run eval -- --model gemini-3.5-flash --repeats 1`
- **無料枠はモデルごとに1日の回数上限があります**(2026-09-27 時点の実測で `gemini-3.8-flash`・`gemini-3.5-flash` は1日20回。上限値は Google AI Studio の「Rate limit」画面で確認できます)。評価は1回読むごとに `eval/runs/<モデル名>.jsonl` へ保存し、1日の上限に当たると「本日の無料枠を使い切りました」と表示してそれまでの分で集計して終了します。翌日以降に同じコマンドを実行すると続きから再開します
- 画面・CLI・サーバーは Windows 11 + Node.js 22 で起動を確認済み(`npm run dev`・`npm run build && npm start`・`npm run extract`)
- アップロード制限: 最大 10 件・1件 20MB・PDF/PNG/JPG/WEBP のみ。超過や対象外の形式は日本語のエラーメッセージ(JSON)で返し、内部のパスやスタックトレースは返しません。出力時(`/api/export`)はサーバー側で機械チェックをやり直すため、画面側の判定を書き換えても要確認は外せません

## 評価結果(2026-09-27 実施・Gemini API 無料枠)

架空サンプル 14 件(PDF 12 件・画像 2 件。うち「要確認」になるべき誤り入り 7 件)で、本物の Gemini API を呼んで評価しました。金額はすべて完全一致で比較しています。詳細は `eval/results.md`(最後に実行した分)と `eval/runs/*.jsonl`(AI の生の読み取り結果)にあります。

| モデル | 読み取り回数 | 項目別正答率(11項目) | 要確認の振り分け | 回ごとのぶれ |
|---|---|---|---|---|
| gemini-3.5-flash-lite | 14件×1回 = 14回 | 全項目 100% | 14/14 一致 | (1回のみのため対象外) |
| gemini-3.5-flash | 4件×3回 = 12回(1日の無料枠で中断) | 全項目 100% | 4/4 一致 | なし |

- 誤り入りの書類は、AI が印字どおりの(間違った)値を読み、その値を機械チェックが「要確認」に振り分けました。例: 「数量10×単価220=2,300円」の行はそのまま読み取り→チェック1で要確認、存在しない日付「2026-02-30」もそのまま読み取り→チェック6で要確認、発行元の無い領収書は発行元を null として返し→チェック7で要確認。
- **注意**: サンプルはスクリプトで生成したきれいな書類で、スキャン風の画像も軽い傾き・ぼかし程度です。100% は「このサンプルでは」という結果で、実際の書類(手書き・かすれ・複雑なレイアウト)での精度を示すものではありません。実運用では「要確認」行を人が確認する前提です。
- `gemini-3.8-flash`(既定モデル)と `gemini-3.5-flash` の 3 回ずつの評価は、1日の無料枠の範囲で続きを実行する予定です(未完了)。

## テストについて(わざと壊すと失敗することの確認)

- `npm test` は Gemini を呼ばず、偽AI応答(`StubExtractor`)でチェック1〜8の正常/異常、CSV/Excelの読戻しを確認します
- 「わざと壊すと失敗する」ことの確認(2026-09-27、現在の 44 件で実施): `src/validate.ts` の合計チェック(`checkTotal`)を一時的に常に `[]` を返すようにして `npm test` → 4 件失敗(チェック4 の異常系、CLI の要確認出力、`/api/export` のサーバー側再検証、`/api/validate` の再判定)。元に戻して 44/44 通過を確認
- 実施記録のコミットには壊した変更は含めない
